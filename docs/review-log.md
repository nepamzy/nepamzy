### Recovery decision gate (owner decision required)

Verified safe mechanism: **backup TOTP factor enrolled while still aal2** (item 13). Implemented in Batch 1 as an optional-for-customers, offered-to-all enrollment path. Whether to _require_ a backup factor for privileged roles is **proposed to the owner, not imposed**.
**Not implemented — STOP for owner decision:** recovery when _all_ factors are lost. The only technically available route is admin-assisted factor deletion via the Admin API (item 12), which leaves the account protected by password alone and does not revoke sessions. A secure version would need at minimum: out-of-band identity verification (undefined, institution-dependent), two distinct aal2 admins, session revocation, holder notification, a cooling-off delay, forced immediate re-enrollment, and full audit. That is a process/policy design that needs the owner's decision (and AFIT's identity-verification rules). Until then: lost all factors = account locked; documented in `docs/security-privacy.md`.

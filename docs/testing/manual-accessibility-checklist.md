# Manual accessibility checklist (for a person with a device)

**This is a checklist, not evidence.** Nothing in it has been performed unless a row says so. Status vocabulary: Automated (script passed) · Manual verified (a named person did it, date) · Blocked (cannot be done here) · Requires person/device.

| #   | Check                                                                                                                                           | Where                                                                          | Status today                                                                                      |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| 1   | Keyboard only: every control reachable, visible focus, logical order                                                                            | Sign-in, MFA, cart, checkout, order, notifications, vendor, rider, admin pages | Automated (12 screens + MFA + signature panel, `accessibility-keyboard.spec.ts`); person not done |
| 2   | Focus after errors and after actions (does focus move to the message?)                                                                          | Forms with server errors                                                       | Requires person                                                                                   |
| 3   | Screen reader (NVDA/JAWS on Windows, VoiceOver on iOS/macOS, TalkBack on Android): headings, landmarks, form labels, status/alert announcements | All critical flows                                                             | Blocked (no screen reader here); requires person/device                                           |
| 4   | Zoom 200 % and 400 %, text-only zoom, high contrast / forced colours                                                                            | All pages                                                                      | 320 px reflow automated; the rest requires person                                                 |
| 5   | Touch targets and one-handed use on a real phone                                                                                                | Rider and vendor flows                                                         | Requires device                                                                                   |
| 6   | Dialogs and menus (focus trap, Escape, return focus)                                                                                            | No dialog component is used in the app today                                   | Not applicable until one is used                                                                  |
| 7   | Signature completion and recovery with touch, stylus and mouse; with a switch or voice control; error recovery after a missing signature        | Delivery confirmation                                                          | Requires person/device; keyboard-only is a known gap (K27)                                        |
